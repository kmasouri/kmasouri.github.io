# kmasouri.github.io

My personal blog: a static [Astro](https://astro.build) site that boots like an old PC.
A BIOS POST screen ([TuiCss](https://github.com/vinibiavatti1/TuiCss)) hands off to a
Windows XP desktop ([XP.css](https://botoxparty.github.io/XP.css/)), and every post opens
as a window. It's hosted for free on GitHub Pages.

Under the costume it's a normal website: every post has its own URL, pages are plain
HTML that works without JavaScript, and there's a sitemap.

## Run it locally

You need [Node.js](https://nodejs.org) 22.12 or newer (the deploy workflow uses Node 24).

```sh
npm install        # once
npm run dev        # http://localhost:4321, live-reloads as you edit
npm run build      # production build into dist/
npm run preview    # serve dist/ locally to double-check a build
```

Tip: the boot screen only plays once per browser session. To see it again, use
**Start → Restart**, or open the site in a new private window.

## Write a new post

1. Copy `src/content/posts/markdown-cheatsheet.md` to a new file, e.g.
   `src/content/posts/my-first-real-post.md`.
   **The file name becomes the URL:** `/posts/my-first-real-post/`. Use lowercase
   words separated by hyphens.
2. Edit the frontmatter at the top:

   ```yaml
   ---
   title: "My First Real Post"
   date: 2026-10-12              # YYYY-MM-DD, used for sorting (newest first)
   description: "One sentence for the post list and search results."
   tags: [notes, homelab]        # optional
   draft: true                   # optional; true = only visible in `npm run dev`
   ---
   ```

3. Write the post in Markdown below the frontmatter. Start sections at `##`, because the
   title is already the page's `#` heading.
4. Images go in `src/assets/blog/` and are linked relatively with alt text:
   `![What the image shows](../../assets/blog/photo.jpg)`. Astro optimizes them at build time.
5. Preview with `npm run dev`, set `draft: false`, then commit and push. The site
   redeploys automatically.

If the frontmatter is wrong (missing title, bad date), the build fails with a message
that names the file and field. The schema lives in `src/content.config.ts`.

### Moving posts over from Notion

In Notion, use **••• → Export → Markdown & CSV** on a page. Rename the exported `.md` file
to a URL-friendly slug, add the frontmatter block above, move any images into
`src/assets/blog/`, and fix the image paths.

## Where things live

```
src/
  content/posts/        ← your posts (Markdown)
  data/about.md         ← text of the "About Me" window
  consts.ts             ← site title, description, name, email, GitHub link
  content.config.ts     ← frontmatter schema for posts
  components/
    BootScreen.astro    ← BIOS screen and the POST lines it types out
    XPWindow.astro      ← reusable XP window (title bar, min/max/close)
    Taskbar.astro       ← taskbar, Start menu, clock
    DesktopIcons.astro  ← desktop shortcuts
  layouts/Desktop.astro ← page shell: <head>/SEO, wallpaper, icons, taskbar
  pages/
    index.astro         ← desktop (+ boot screen)     → /
    posts/index.astro   ← "My Blog" folder window     → /posts/
    posts/[id].astro    ← one window per post         → /posts/<slug>/
    about.astro         ← Notepad window              → /about/
    recycle-bin.astro   ← a joke                      → /recycle-bin/
    404.astro           ← blue screen of death        → any missing URL
  scripts/
    boot.ts             ← boot animation (skippable, once per session)
    desktop.ts          ← clock, window dragging/minimize/maximize
  styles/
    global.css          ← desktop, taskbar, Start menu, window layout, post typography
    boot.css            ← BIOS screen (TuiCss loaded into a low-priority CSS layer)
public/                 ← copied as-is: icons, wallpaper, favicon, robots.txt, og.png
```

The sitemap (`/sitemap-index.xml`) is generated by `@astrojs/sitemap`.

### How the pieces fit

- **Every window is a real page.** `/posts/my-post/` renders the whole desktop with
  that post's window already open, so direct links, bookmarks, and search engines all
  work. Desktop icons and Start menu entries are ordinary links.
- **Boot screen:** plays only on `/`, once per browser session (tracked in
  `sessionStorage`). Any key, click, or tap skips it. Landing on any other page counts
  as "already booted", so direct links never show it. With
  `prefers-reduced-motion`, the lines appear instantly and the screen moves on after a
  moment.
- **Windows:** drag by the title bar on screens 768px and wider. Double-click the title
  bar or press the Maximize button to maximize. Minimize sends the window to the taskbar.
  Close goes back to the desktop (posts close to the My Blog folder). On phones, windows
  always fill the screen above the taskbar, and dragging is off.
- **No framework:** two small vanilla TypeScript files. The Start menu is a native HTML
  `popover`, so it works without JavaScript, closes on Escape or an outside click, and is
  keyboard accessible.

### Customizing

- **Name, links, site description:** `src/consts.ts`
- **About text:** `src/data/about.md` (replace the `TODO` lines)
- **Wallpaper:** replace `public/wallpaper.svg`, or point `body { background }` in
  `src/styles/global.css` at your own image
- **Desktop icons:** `src/components/DesktopIcons.astro`
- **BIOS lines:** the `steps` array in `src/components/BootScreen.astro`
- **Social preview image:** `public/og.png` (1200×630)

## Deployment (GitHub Actions → GitHub Pages)

`.github/workflows/deploy.yml` is the official Astro workflow. On every push to `main`,
[`withastro/action`](https://github.com/withastro/action) installs dependencies, runs
`astro build`, and uploads `dist/`, and `actions/deploy-pages` publishes it. You can also
run it by hand from the **Actions** tab ("Run workflow").

The site is served from the domain root because this is a *user site*: the repository
must be named exactly **`kmasouri.github.io`**. That's why `astro.config.mjs` sets
`site: 'https://kmasouri.github.io'` and no `base`.

### One-time setup

1. Create an **empty, public** repository on GitHub named `kmasouri.github.io`. Don't
   add a README, .gitignore, or license. (Free accounts need a public repo for Pages.)
2. Push this project:

   ```sh
   git remote add origin git@github.com:kmasouri/kmasouri.github.io.git
   # or: https://github.com/kmasouri/kmasouri.github.io.git
   git push -u origin main
   ```

3. In the repository, go to **Settings → Pages → Build and deployment → Source** and
   choose **GitHub Actions**. (The default, "Deploy from a branch", won't run the workflow
   output.)
4. Open the **Actions** tab. If the first run started before you changed the setting and
   failed, click it and choose **Re-run all jobs**, or use **Run workflow**.
5. After the green check, the site is live at <https://kmasouri.github.io/>. The first
   deploy can take a minute or two to appear.

After that, publishing a post is just: write → commit → `git push`.

### Optional

- In Settings → Pages, **Enforce HTTPS** should already be on for `github.io` domains.
- To add a custom domain later: add it in Settings → Pages, add a `public/CNAME` file
  containing the domain, and change `site` in `astro.config.mjs`.

## Notes

- `npm run build` prints a lightningcss warning about a `progress:not([value]):after`
  selector in XP.css. It's harmless: that rule (an indeterminate progress bar) isn't used
  here and is dropped. See the `vite.css.lightningcss` comment in `astro.config.mjs`.
- XP.css and TuiCss are MIT-licensed. The icons and wallpaper in `public/` are original
  SVGs drawn for this site, not Microsoft assets.
